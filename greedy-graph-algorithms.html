Greedy Algorithm

Take the best option available right now and never look back.

Concept

A greedy algorithm builds a solution piece by piece, always choosing the locally best option. It works when the problem has two properties: the greedy-choice property (a local optimum leads to a global optimum) and optimal substructure (the rest of the problem is a smaller copy of the same problem). It is fast and simple, but for some problems it gives wrong answers, so it must be proven correct.

General steps

  1. Define the candidate choices.
  2. Pick the best one by a fixed rule (largest, smallest, earliest…).
  3. Check that it is feasible; keep it if yes.
  4. Repeat until the problem is solved.

Real-life example

Giving change at a shop: to return ₹289 you hand over the biggest note or coin that fits (₹100, ₹100, ₹50 …) until nothing is left. It is quick and, for Indian denominations, optimal.

Operating System link

Shortest Job First (SJF) CPU scheduling always picks the process with the smallest burst time, which minimises average waiting time. Disk scheduling (SSTF) is greedy too: serve the nearest track first.
Where greedy fails: coins {1, 3, 4}, amount 6. Greedy gives 4+1+1 (3 coins) but the best is 3+3 (2 coins). This is why Dijkstra needs non-negative weights, and why some problems need dynamic programming.

Dijkstra's Algorithm

Single-source shortest path, non-negative weights.

Concept

Starting from a source, Dijkstra repeatedly finalises the closest unvisited node. Once a node is finalised, its distance is guaranteed shortest, because every other path would have to pass through a node that is already farther away. That is the greedy choice.

Steps

  1. Set dist(source)=0 and all others ∞.
  2. Pick the unvisited node u with the smallest distance.
  3. Mark u visited.
  4. Relax every edge (u,v): if dist(u)+w < dist(v), update dist(v).
  5. Repeat until all nodes are visited.

Complexity

Array: O(V²)
Binary heap: O((V+E) log V)
Space: O(V)
Fails with negative edges.

Real-life example

Google Maps finding the fastest road from your home to the airport. Each junction is a node, each road is an edge and travel time is the weight.

Operating System link

OSPF routing in the network stack of an OS and routers runs Dijkstra on the link-state map to fill the routing table.

Bellman-Ford Algorithm

Shortest paths that survive negative edges.

Concept

Instead of trusting the closest node, Bellman-Ford relaxes all edges again and again. After pass k, all shortest paths using at most k edges are correct. A shortest path has at most V−1 edges, so V−1 passes are enough. If a V-th pass still improves something, a negative cycle exists.

Steps

  1. Set dist(source)=0, others ∞.
  2. Repeat V−1 times: for each edge (u,v,w) relax it.
  3. Run one more pass: if any distance still drops, report a negative cycle.

Complexity

Time: O(V·E)
Space: O(V)
Slower than Dijkstra but handles negative weights.

Real-life example

Currency exchange. Convert rates to logarithms, and a negative cycle means an arbitrage: a loop of trades that makes free money.

Operating System link

The RIP protocol (distance-vector routing) is a distributed Bellman-Ford: each router shares its table with neighbours and relaxes routes.

Floyd-Warshall Algorithm

All-pairs shortest paths with dynamic programming.

Concept

Floyd-Warshall answers "what is the shortest path between every pair of nodes?" It allows intermediate nodes one at a time. After processing node k, dist[i][j] is the best path from i to j using only the first k nodes as stops.

Steps

  1. Build a matrix: 0 on the diagonal, edge weight where an edge exists, ∞ otherwise.

  3. If dist[i][k]+dist[k][j] < dist[i][j], update dist[i][j].
Core line: d[i][j]=min(d[i][j], d[i][k]+d[k][j])

Complexity

Time: O(V³)
Space: O(V²)
Handles negative edges (not negative cycles). Ideal for small dense graphs.

Real-life example

A flight app that pre-computes the cheapest fare between every pair of cities, so any query is a table look-up.

Operating System link

Building a full routing table for a small network, and computing the transitive closure of resource-allocation graphs used in deadlock analysis.

Prim's Algorithm

Grow one tree, one cheapest edge at a time.

Concept

A Minimum Spanning Tree (MST) connects all nodes with the lowest total edge weight and no cycles. Prim starts from one node and keeps expanding the tree with the cheapest edge that reaches a new node. By the cut property, that edge always belongs to some MST.

Steps

  1. Start with any node in the tree.
  2. Look at all edges leaving the tree.
  3. Add the cheapest one and its new node.
  4. Repeat until all V nodes are in (V−1 edges).

Complexity

Heap: O(E log V)
Matrix version: O(V²)
Best for dense graphs.

Real-life example

Laying fibre-optic cable between offices of a company using the least total cable length.

Operating System link

Spanning trees stop switching loops and broadcast storms in LANs (the idea behind the Spanning Tree Protocol).

Kruskal's Algorithm

Sort all edges, accept those that do not form a cycle.

Concept

Kruskal also builds an MST, but it thinks in edges instead of nodes. It sorts every edge by weight and accepts the cheapest edge unless it would close a cycle. A Disjoint Set Union (Union-Find) structure checks in almost constant time whether two nodes are already connected.

Steps

  1. Sort edges by weight, ascending.
  2. For each edge (u,v): find the sets of u and v.
  3. If the sets differ, accept the edge and union them.
  4. Otherwise reject it (cycle).
  5. Stop after V−1 accepted edges.

Complexity

Time: O(E log E)
Space: O(V)
Best for sparse graphs.

Real-life example

A government connecting villages by roads: build the cheapest roads first, skip any road that links villages already connected.

Operating System link

Union-Find is the same structure used to group connected components, e.g. detecting groups of processes or resources that are linked together.

Exam tips

  • Dijkstra, Prim and Kruskal are greedy; Floyd-Warshall is dynamic programming; Bellman-Ford is repeated relaxation.
  • Shortest path tree ≠ minimum spanning tree: one minimises distance from a source, the other minimises total weight.
