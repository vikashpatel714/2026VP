1. What is Memory Management?

RAM is the CPU's desk. Many programs (processes) want space on it at the same time. The Memory Manager (part of the OS) decides who gets which part.

🗺️Track
Which bytes are free / used
📥Allocate
Give memory to a process
♻️Deallocate
Take it back when done
🛡️Protect
Process A can't touch B
🔄Swap
RAM full? Move to disk
🤝Share
Common code (libraries)
🏨 Real life: RAM = hotel. Processes = guests. Memory manager = front desk: it tracks empty rooms, gives keys (allocate), collects keys at check-out (deallocate), stops guests entering others' rooms (protect).

3. Address Binding

Programs use logical (virtual) addresses. RAM uses physical addresses. Turning one into the other is binding.

When?HowNote
Compile timeCompiler knows exact RAM location → absolute codeMust recompile if location changes
Load timeRelocatable code; fixed when loadedReload to move
Execution timeDone on every access by the MMUProcess can move while running (used by modern OS)

▶ MMU simulator: Physical = Relocation (base) register + Logical, if Logical < Limit

📮 Real life: Apartment "Flat 5" inside your building (logical) is really "Building 14000 + 5" in the city (physical). Going beyond your own building's flats → security stops you (trap).

Two kinds of waste (fragmentation)

  • Internal: wasted space inside an allocated block (you took a big room, used a corner).
  • External: enough total free space, but scattered in small holes – no single hole is big enough.

5. Contiguous – Fixed Partitions

RAM is divided into partitions of fixed sizes in advance. Each partition holds one process. Simple and fast, but a process smaller than its partition wastes the rest = internal fragmentation. Also limits the number of processes and max process size.

🚌 Real life: Buses with fixed seating sections. A family of 3 gets a 10-seat compartment – 7 seats wasted, nobody else can use them.

6. Contiguous – Variable Partitions & Allocation Strategies

Partitions are created on demand exactly the size of the process → no internal waste. But as processes leave, holes appear → external fragmentation. Fix: Compaction (slide all processes together – costly).

Which hole to pick?

🥇First Fit
First hole big enough. Fast.
🎯Best Fit
Smallest hole big enough. Leaves tiny useless holes; slow search.
🐘Worst Fit
Largest hole. Leaves big leftover; usually worst performance.
🅿️ Real life – parking: First fit = take the first empty slot you see. Best fit = squeeze into the tightest slot. Worst fit = park in the biggest empty area.

7. Non-Contiguous – Paging

Logical memory is cut into equal pages; physical RAM into equal frames (same size). Any page can go into any free frame – no external fragmentation (only a little internal waste in the last page). The page table maps page → frame. A fast cache of recent entries is the TLB.

Logical address = (page number p, offset d) → Physical = frame × page size + d

📚 Real life: A book's chapters (pages) are stored on random shelves (frames). The index card (page table) tells you the shelf of each chapter. TLB = sticky note with the shelves you used recently.

8. Non-Contiguous – Segmentation

Memory is split by meaning: Code, Data, Stack, Heap – each a segment of different size. Address = (segment s, offset d). Segment table stores base and limit. If d ≥ limit → trap. Matches how programmers think, easy sharing/protection, but causes external fragmentation.

🏢 Real life: An office with departments (HR, Sales, IT) of different sizes. You address someone as "Department + desk number".

9. Segmented Paging

Best of both: first divide into segments, then page each segment. Each segment has its own page table. Address = (s, p, d). Path: Segment table → that segment's page table → frame + offset. No external fragmentation, still has logical structure.

🏬 Real life: A company (process) has departments (segments). Each department's files are stored in same-size boxes (pages) placed in any free cupboard slot (frames).

  • First fit = fastest · Best fit = tightest, tiny holes · Worst fit = biggest hole.
  • Physical (paging) = frame × size + offset · Physical (segmentation) = base + offset (offset < limit).
  • Internal waste = inside block · External waste = between blocks.
