1. Process & Thread Management — Concepts

A process is a program in execution — it has its own memory (code, data, stack, heap) and is managed by the OS via a Process Control Block (PCB) storing PID, state, registers, priority, etc. A thread is a lightweight unit of execution inside a process; multiple threads of one process share the same memory but have separate stacks.

Process State Diagram

ProcessThread
Heavyweight, own address spaceLightweight, shares parent's address space
Context switch is slow (costly)Context switch is fast (cheap)
Communication needs IPCCommunication via shared memory (fast)
Independent — crash doesn't affect othersCrash can affect whole process
Real-life analogy: A process is like an entire office building (own resources, own address). Threads are like employees working inside that same building sharing the same furniture/files (memory) — much cheaper to hire/manage than opening a new building each time.

2. Introduction to C Programming — Building Blocks

a) Statement

A statement is one complete instruction ending with ;.

int a = 5;      // declaration statement
printf("Value = %d", a); // function-call statement
Output: Value = 5

b) Conditional Statement (if-else)

#include <stdio.h>
int main(){
    int num = 7;
    if (num % 2 == 0)              // check divisibility by 2
        printf("Even");
    else
        printf("Odd");              // runs when condition is false
    return 0;
}
Output (Turbo C / GCC): Odd

c) Loop (for)

for(int i = 1; i <= 5; i++){   // init; condition; increment
    printf("%d ", i);           // runs 5 times
}
Output: 1 2 3 4 5

d) Array

int marks[5] = {90,80,70,60,50}; // fixed-size collection
for(int i=0;i<5;i++)
    printf("%d ", marks[i]);   // indices 0..4
Output: 90 80 70 60 50

e) Function

int square(int x){      // function definition, takes x, returns int
    return x*x;         // return statement sends value back
}
int main(){
    printf("%d", square(4)); // function call, prints 16
    return 0;
}
Output: 16

🧩 Code Explained — From Absolute Scratch (Easy English)

This page has 3 parts: HTML (the structure — tables, buttons, headings), CSS (only colors/styling — has nothing to do with the algorithm logic), and JavaScript (the actual logic that runs the scheduling). Below, only the JavaScript logic part is explained step by step — that is the part that really matters.

Step 1 — The Process Table (storing the data)

let procs=[{pid:1,at:0,bt:5,pr:2}, ...];

This is an array of objects — each process's data is stored as one object:

  • pid = Process ID (P1, P2...)
  • at = Arrival Time (when the process requests the CPU)
  • bt = Burst Time (how much CPU time it needs in total)
  • pr = Priority (lower number = higher priority)

renderTable() displays this data as an HTML table. When you change a value in an input box, onchange="procs[i].at=+this.value" runs — meaning as soon as you edit a value, the JavaScript array updates instantly.

Step 2 — cloneProcs() (making a working copy)

function cloneProcs(){return procs.map(p=>({...p, rem:p.bt}));}

This makes a copy of the original procs array and adds one new field, rem (remaining burst time). This is necessary because during simulation we keep reducing the burst time as the process runs on the CPU — but the original table's real data must stay untouched.

Step 3 — timeStepSim(mode) — the most important function

This single function handles FCFS, SJF, and Priority scheduling. The idea is very simple:

Move time forward one unit at a time (t = 0, 1, 2, 3...), and at every unit, decide which process should run on the CPU right now.
while(done<n && t<maxT){
  let cand = list of processes that have arrived AND are not yet finished;
  // now pick one candidate, depending on the mode:
  if(mode==='fcfs')     → pick whoever arrived first
  if(mode==='sjf_np')   → pick smallest burst time (but don't interrupt once started)
  if(mode==='sjf_p')    → RECHECK every unit; switch if a shorter job shows up
  if(mode==='prio_np')  → pick highest priority, don't interrupt once started
  if(mode==='prio_p')   → recheck every unit; switch based on priority

  ps[pick].rem--;    // that process just completed 1 unit of work
  t++;               // move the clock forward by 1 unit
  if(rem==0) done++; // process has fully finished
}
Small example (FCFS): P1 arrives at time 0, burst 5 sec → runs on CPU from 0 to 5. P2 arrives at time 1, burst 3 sec → runs from 5 to 8 (because P1 arrived first). That is exactly what this loop computes.

Step 4 — simulateRR(quantum) — Round Robin

Here a queue (line) is maintained — just like a queue at a bank:

  • Take out the process at the front — queue.shift()
  • Let it run only for the quantum (e.g. 2 sec), not its full burst
  • If it isn't finished yet → send it back to the end of the line — queue.push(cur)
  • Newly arriving processes also join the line

This is what makes Round Robin fair — no single process can hog the CPU for too long.

Step 5 — simulateMLQ — Multilevel Queue

Two separate queues are maintained:

  • q0 = System processes (priority ≤ 2) — scheduled using Round Robin
  • q1 = User processes (priority > 2) — scheduled using FCFS
The rule is simple: as long as q0 (system queue) has any process, q1 (user queue) doesn't get a turn at all. Real operating systems work the same way — system-level work is always handled before ordinary user programs.

Step 6 — renderResult() — displaying the result

This function takes the scheduling output and builds two things:

  1. The Gantt chart — colored blocks showing which process ran on the CPU and during which time range
  2. The result table — Completion Time (CT), Turnaround Time (TAT), Waiting Time (WT)
Formulas worth memorizing (these come up in exams too):
TAT = Completion Time − Arrival Time
WT = Turnaround Time − Burst Time

Step 7 — the ALGOS array + runAlgo() — ties everything together

Near the bottom of the script there's one big list called ALGOS, containing each algorithm's name, C code, and explanation. A loop then automatically builds the full section (code block + button + chart) for every algorithm in HTML — so the same layout didn't have to be written by hand six separate times.

When you press the "▶ Run Simulation" button, a call like runAlgo('fcfs') is triggered, which runs the correct scheduling function (timeStepSim / simulateRR / simulateMLQ) and displays the result on screen.
